# AGENTS.md — operating manual for agent-patterns

## 1. Charter

> **80/20. Usable this week. Good-enough decisions.**
> This is an MVP that is meant to be used, found wrong, and fixed while in use.
> Do not add ceremony. If a rule in this spec does not help an AI agent (or Jonathan)
> get better results in a coding session, drop the rule and log that you dropped it.
> The only decisions worth agonizing over are the ones that would be expensive to
> reverse later (listed in SPEC §3). Everything else: pick, log, move on.

## 2. Schema summary

Full formats: [SPEC.md](SPEC.md) §5. Short version:

- `patterns/<slug>.md` — one file per pattern/anti-pattern. Flat directory;
  category is a frontmatter tag, never a folder. Frontmatter: `id` (== slug,
  never changes; rename = new file + `aliases:` entry), `title`, `type`
  (pattern|anti-pattern), `status` (candidate|adopted|deprecated|absorbed),
  `durability` (structural|compensation|unknown), `scope`
  (interactive|long-running|both), `tools` (both|claude-code|codex),
  `category`, `verified` (date), `models` (families judged against),
  `confidence` (high|medium|low), `sources` (bib ids), `related`, `aliases`.
  Body ≤ ~250 words, headings in order: **Use when / Do / Why / Don't, when
  not / Evidence / Tool notes**. Drop a heading rather than pad it. Every
  Evidence line points at a note in `sources/` or `[own]` with a date.
- `sources/<bib-id>.md` — one note per source with relevance ≥ medium.
  Frontmatter: `id`, `title`, `author`, `date`, `url`, `access`
  (direct|signup|paid|gmail), `accessed`, `scope`, `relevance`, `pass`
  (triage|distilled), `patterns` (back-links). Sections: Summary (≤ 150 words,
  own words) / Takeaways for our use case / Candidate patterns / Other-use-case
  material. Bib ids: `<author-or-org>-<yyyy>-<short>`; Every newsletters:
  `every-<yyyy-mm-dd>-<slug>`.
- `sources/_triage.md` — one row per item ever triaged:
  `id | date | title/author | relevance | scope | note-exists? | one-line takeaway`.
- `bibliography.md`, `quickref.md`, `skill/agent-patterns/patterns-list.md`,
  and the "recently changed" block in `index.md` are **generated by lint** —
  edit patterns and source notes, not these.

## 3. Workflows

### advise (strategy for a task)
1. Read `index.md`.
2. Pick 3–7 patterns by task shape; read only those files.
3. Return a ≤ 15-line strategy citing pattern ids.
4. If the task reveals a gap, add one line to `inbox.md`.

### ingest (new source)
1. Fetch raw material into `.cache/` (gitignored — never into git).
2. Triage (Sonnet subagent, template in `.claude/agents/source-triage.md`);
   append the row to `sources/_triage.md`.
3. If relevance ≥ medium, distill (Opus subagent) into `sources/<id>.md`.
4. Add/extend patterns: `status: candidate` for new ones; a new Evidence line
   for existing ones.
5. Append 1–5 lines to `log.md`.

### retro (end of a real coding session)
1. Append 1–3 one-line lessons to `inbox.md`: `- YYYY-MM-DD [project] lesson…`.
   No structure, no polish. This is the only workflow Jonathan triggers by habit.

### lint (after every ingest batch; otherwise monthly or at a major model release)
1. Empty `inbox.md` into patterns (new candidate, new evidence line, or discard).
2. Merge duplicate patterns; promote candidates with ≥ 2 evidence lines to
   `adopted` (ask if unsure).
3. Flag pages whose `verified` predates the latest model release; re-rate
   durability where a model change plausibly matters.
4. Regenerate `quickref.md` (≤ 60 lines, adopted only, grouped before
   starting / while working / before finishing, each line ending with the
   pattern id in brackets), `bibliography.md`, `skill/agent-patterns/quickref.md`,
   `skill/agent-patterns/patterns-list.md`, and the "recently changed" block in
   `index.md`.
5. Log a 3–5 line summary.

### experiment
1. Write it in `experiments.md`: hypothesis, change made, success criterion,
   revisit date. Allowed without asking; log it.
2. On revisit, keep or revert; record the outcome.

### release
Merge the feature branch to `main` at a checkpoint, only after Jonathan's OK.

## 4. Guardrails (short form)

- Everything lives under `agent-patterns/`. No files or side effects elsewhere.
  Relative links only; no absolute paths in content.
- Sources are summaries + links only. Never commit article text, newsletter
  bodies, or exports; raw material stays in `.cache/` (gitignored).
- Only use material fetchable directly. Signup-gated → `access: signup` in the
  bibliography, log it, move on. Paid → out of scope; training-only knowledge
  gets `confidence: low` at most, or is left out.
- No hallucinated evidence: every Evidence line traces to an existing source
  note or `[own]` experience with a date. Paraphrase; at most one short
  attributed phrase per source.
- Cross-tool by default: write tool-neutral; tool mechanics go on marked
  `Claude Code:` / `Codex:` lines. `tools: both` unless there's a concrete reason.
- Long-running-agent / builder-side material is flagged as another use case
  (`scope: long-running` or `builder`) and never enters `quickref.md`.

## 5. Permission to experiment

Experiments on structure and process are allowed **without asking** (SPEC D12),
provided they are logged in `experiments.md` with a success criterion and a
revisit date. Lint cadence: after every ingest batch; otherwise monthly or at
any major model release.

## 6. Tool notes

- **Claude Code:** `CLAUDE.md` here is just `@AGENTS.md` (import bridge). Build
  and maintenance subagents live in `.claude/agents/` (`source-triage.md`,
  `source-distill.md`). Skills load from `~/.claude/skills/`; symlink
  `skill/agent-patterns` there. Run sessions with `agent-patterns/` as the
  working directory so this `.claude/` and `CLAUDE.md` are the project scope.
- **Codex:** reads `AGENTS.md` natively. Skills load from `~/.codex/skills/`
  (path to verify); symlink `skill/agent-patterns` there. Custom agents would
  be TOML under `.codex/agents/` — not maintained for the MVP.
