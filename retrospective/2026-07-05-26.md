## Part 1 — what happened

### Phase 1 — Intake and the one-question gate

The session prompt was "read `tasks/task-01-artifact-model.md`, treat it as a
prompt, ask questions before I leave." Instead of asking immediately, the
session first read the task, README, all four profiles, and both sibling task
files — which eliminated nearly every candidate question: the task text itself
delegated the known classification tension ("your model must take a position"),
and tasks 02/03 answered how downstream vocabulary would be consumed. Exactly
one genuine fork survived: how much freedom existed to change artifact IDs that
task-02/03 already cite. One `AskUserQuestion` ("Stable IDs, additive OK" won),
plus a stated-defaults list (Mermaid, syntax position, PR-references-not-closes,
task files untouched) offered as a veto window. All defaults held unchallenged
through merge. The pattern is written up as a skill candidate
(`single-question-clarification-gate`).

### Phase 2 — Evidence fan-out plus own crux reads

The four gold specs (7,911 lines) were fetched to scratchpad and verified
byte-identical in line count to what the profiles measured (2,090 / 1,467 /
2,169 / 2,185) — making the profiles' line citations safely reusable. Four
background general-purpose analysts were dispatched, one per spec, each brief
inlining the full hypothesized artifact model (subagents share no memory),
demanding line-cited classification of every heading, misfit flagging
("a flagged misfit is more valuable than a strained classification"), audit-
defect verification, exemplar nomination, and a verdict on a stated working
position (concrete syntax → R-IS). While they ran, the dispatcher read the
crux sections itself — the four architecture sections, the DOT grammar seam,
symphony's normative preamble and validation profiles, the byte-for-byte
mandate, and all four hypothesized exemplars.

The overlap was deliberate and paid off twice: the independent analysts
converged on the same model hole (no home for architecture content — two
proposed the same artifact independently), and the dispatcher's own reads
settled design questions before the agents returned.

### Phase 3 — Design freeze and concurrent front-half authoring

With crux reads done and agents still running, the model was frozen (16
artifacts, T1–T7, tag grammar, compilation slots) and the document's front
half (§1–§7) written directly to the repo working tree. Pipelining authoring
against agent runtime cost nothing: the front half depended on design
decisions already made, and the validation half (§8–§11) genuinely needed the
inventories.

### Phase 4 — Finding integration: five deltas, all evidence-forced

The analysts' reports forced exactly the right kind of changes — definition-
level, ID-stable: R-AS added (architecture); A-GL extended to conventions;
A-VS extended to own the dependency register (with an inspiration-only vs.
pinned-oracle rule the coding-agent-loop analysis demanded); observable-value
formulas moved R-RA → C-BC (a genuine refutation: symphony keeps its backoff
formula in contract prose and §16 invokes it abstractly); G-CM generalized to
matrix-or-profiles and made conditional (attractor's "parity matrix" is a flat
scenario list). One proposed new artifact was declined (a built-in-component
catalogue — folded into R-IS instead, preserving minimality). The
formulas-in-C-BC refutation is the session's best evidence that giving
analysts a working position *to attack* beats asking them to confirm one.

### Phase 5 — Validation sections and QA

§8 (four decomposition tables), §9 (all 14 audited defects re-expressed as
model violations — none required a new rule; 11 further defects surfaced
beyond the audits, mostly gate-vs-body drift), §10 (all four exemplar
hypotheses verified, two with caveats), §11 (ten findings). The Mermaid DAG
was validated via the Mermaid MCP tool — whose result (177,747 chars of
rendered SVG/PNG) exceeded the token cap and had to be `jq`-probed from the
saved tool-result file for the one `valid: true` field. The mandated re-read
pass (two iterations) caught four real drift bugs in the session's own
document, the worst being a DAG-argument sentence claiming "three intra-layer
edges" while listing four, with the true count being seven — a written-from-
memory numeric claim about an artifact sitting right there to count.

### Phase 6 — Ship, field questions, merge, and a mid-retro convention upgrade

Commit → push → PR #26 (ready for review, referencing #22 without closing it,
task acceptance checklist ticked in the body). PR babysitting via
subscription + a `send_later` hourly self check-in (repo has no CI; check-in
found no changes once and re-armed silently). The owner asked whether the

asked-for feature to present (T1–T7 referential integrity, artifact-level
required/conditional status) vs. deliberately deferred (field-level schemas

## Part 3 — agents-file suggestions

Proposed additions to the project's agents file (`AGENTS.md`). Each rule has
its own per-rule file in the sibling directory — exactly two sections:
`# agent instruction` (the verbatim rule text a CI/CD assembler concatenates
into `AGENTS.md`) and `# justification` (persuasion text the assembler
strips). This Part 3 mirrors that content inline so the reviewer has every
proposed rule + its justification in one place at decision time.

### Suggestion 1: Count, don't recall — `AGENTS-MD-1405b870f3`

- **Per-rule file**: [./2026-07-05-26/AGENTS-MD-1405b870f3-count-dont-recall.md](./2026-07-05-26/AGENTS-MD-1405b870f3-count-dont-recall.md)

**Proposed agent instruction** (verbatim from the per-rule file's `# agent instruction` section):

> **Count, don't recall.** Any numeric claim in a document about a structure that exists in the same document (edges in a graph, rows in a table, items in a list) must be derived by counting the structure at write time — grep/wc or explicit enumeration — never written from memory. Re-verify every such claim after editing the structure.
>
> *Grounded in: the artifact-model DAG paragraph claiming "three intra-layer edges" while listing four, with the true count being seven.*

**Justification** (verbatim from the per-rule file's `# justification` section):

The Mermaid graph, the edge-justification table, and the prose acyclicity argument were all in one file, and the prose still contradicted the graph it sat next to — written from a stale mental snapshot two edits earlier. It survived until a mandated full re-read (PR #26, re-read iteration 1). The rule costs one grep per claim; the failure mode ships a self-contradicting document whose whole point is teaching others to avoid self-contradiction.

### Suggestion 2: Brief analysts to refute — `AGENTS-MD-7c326c8d17`

- **Per-rule file**: [./2026-07-05-26/AGENTS-MD-7c326c8d17-brief-analysts-to-refute.md](./2026-07-05-26/AGENTS-MD-7c326c8d17-brief-analysts-to-refute.md)

**Proposed agent instruction** (verbatim from the per-rule file's `# agent instruction` section):

> **Brief analysts to refute.** When dispatching subagents to validate a hypothesis, model, or classification, state the working position explicitly and instruct them to gather evidence for AND against, ending with a verdict. Never phrase the brief so agreement is the easy path.
>
> *Grounded in: the formulas-belong-in-R-RA hypothesis, refuted by the symphony analyst with line evidence, producing the session's best definition fix.*

**Justification** (verbatim from the per-rule file's `# justification` section):

Four analysts were told the working position (concrete syntax → R-IS) and asked for a verdict with evidence. Three confirmed with useful nuance; one refuted an adjacent placement outright — symphony keeps its backoff formula in contract prose and its pseudocode invokes it abstractly — which reversed a planning-session decision before it shipped in PR #26. A confirm-shaped brief would have returned four agreements and a wrong model. Cost: one sentence per brief.

### Suggestion 3: Self-contained briefs — `AGENTS-MD-6ae0c8b46b`

- **Per-rule file**: [./2026-07-05-26/AGENTS-MD-6ae0c8b46b-self-contained-briefs.md](./2026-07-05-26/AGENTS-MD-6ae0c8b46b-self-contained-briefs.md)

**Proposed agent instruction** (verbatim from the per-rule file's `# agent instruction` section):

> **Self-contained briefs.** A subagent brief must inline every definition, list, and convention it depends on — never "the model above" or "as discussed". For large outputs, require the agent to write a file and return only a capped summary (path + findings).
>
> *Grounded in: four spec-analyst briefs, each carrying the full 15-artifact definition block verbatim, returning ≤500-word summaries plus ~160-line inventory files.*

**Justification** (verbatim from the per-rule file's `# justification` section):

The four analysts of the task-01 session produced ~650 lines of line-cited classification without one round-trip clarification, because each brief was executable in isolation. The file+summary split kept four large evidence packages out of the dispatcher's context until each was needed. The marginal cost is duplicated definition text in briefs; the failure mode without it is agents classifying against a model they cannot see.

### Suggestion 4: Trust but read — `AGENTS-MD-8a8938cbe3`

- **Per-rule file**: [./2026-07-05-26/AGENTS-MD-8a8938cbe3-trust-but-read.md](./2026-07-05-26/AGENTS-MD-8a8938cbe3-trust-but-read.md)

**Proposed agent instruction** (verbatim from the per-rule file's `# agent instruction` section):

> **Trust but read.** Before any subagent-reported line citation or exemplar ships in a deliverable, read at least the decisive citations yourself (≥3 per source document). Deliberate overlap between dispatcher reads and agent reads is validation, not waste.
>
> *Grounded in: dispatcher reads of coding-agent-loop §8, symphony §9.5, and unified-llm §6 confirming all four exemplar hypotheses first-hand before §10 of the artifact model asserted them.*

**Justification** (verbatim from the per-rule file's `# justification` section):

The artifact model asserts "verified as hypothesized" about specific sections of external documents. Those assertions were publishable because the dispatcher had read the cited lines, not just the analysts' summaries — and the same overlap independently produced the R-AS convergence signal (two analysts and the dispatcher reaching the same model hole separately). Cost: a few targeted Reads per document.

### Suggestion 5: Role over form — `AGENTS-MD-37213c6f0f`

- **Per-rule file**: [./2026-07-05-26/AGENTS-MD-37213c6f0f-role-over-form.md](./2026-07-05-26/AGENTS-MD-37213c6f0f-role-over-form.md)

**Proposed agent instruction** (verbatim from the per-rule file's `# agent instruction` section):

> **Role over form.** When classifying spec content (this repo's artifact model, checklists, or checkers): the artifact is determined by what the content DOES, never by its notation (BNF, table, prose) or its document position (body vs. appendix). Expect abstract enums written in grammar notation and normative contracts living in appendices.
>
> *Grounded in: attractor writing an abstract enum in BNF (L1141–47) and keeping a normative wire contract in Appendix C.*

**Justification** (verbatim from the per-rule file's `# justification` section):

Every future task in this repo (task-02 authoring, task-03 checkers) classifies spec content. Both obvious mechanical keys — notation and position — misfile real gold-spec content: BNF marks an abstract domain enum, appendices hold first-class failure models, and rationale sits in normative bodies. A checker keyed on surface form will systematically misfire; this rule is the one-line inoculation, and it was load-bearing in all four PR #26 decomposition tables.

### Suggestion 6: Pin the corpus — `AGENTS-MD-267db6c244`

- **Per-rule file**: [./2026-07-05-26/AGENTS-MD-267db6c244-pin-the-corpus.md](./2026-07-05-26/AGENTS-MD-267db6c244-pin-the-corpus.md)

**Proposed agent instruction** (verbatim from the per-rule file's `# agent instruction` section):

> **Pin the corpus.** Before citing line numbers into external documents (the four gold specs or any future corpus), fetch fresh copies and verify line counts match the versions the prior analysis measured (`wc -l` equality). On mismatch, stop and re-anchor before citing.
>
> *Grounded in: the four gold specs matching the profiles' measurements exactly (2,090 / 1,467 / 2,169 / 2,185), which made hundreds of prior line citations safely reusable.*

**Justification** (verbatim from the per-rule file's `# justification` section):

This repo's analysis chain (profiles → artifact model → future checkers) is welded together by line numbers into documents this repo does not control. The check is one `wc -l` per document; skipping it and citing into a drifted upstream would silently corrupt every downstream table. In the task-01 session the check passed and unlocked confident reuse; the day it fails is the day it pays for itself.

### Suggestion 7: jq the saved result — `AGENTS-MD-f79b564822`

- **Per-rule file**: [./2026-07-05-26/AGENTS-MD-f79b564822-jq-the-saved-result.md](./2026-07-05-26/AGENTS-MD-f79b564822-jq-the-saved-result.md)

**Proposed agent instruction** (verbatim from the per-rule file's `# agent instruction` section):

> **jq the saved result.** When an MCP tool result exceeds the token cap and is saved to a file, probe its structure and extract only the fields you need (`jq -r '.valid'`), guided by the schema in the error message. Never Read the raw file into context.
>
> *Grounded in: the Mermaid validator returning 177,747 characters (rendered SVG/PNG inline) for a diagram whose only needed answer was `valid: true`.*

**Justification** (verbatim from the per-rule file's `# justification` section):

The needed answer was one boolean; the payload was ~45k tokens of SVG. One `jq` call retrieved it. The failure mode is an agent flooding its own context with base64 pixels and losing the working state that mattered.

### Suggestion 8: One retry for stream flakes — `AGENTS-MD-d80abce6eb`

- **Per-rule file**: [./2026-07-05-26/AGENTS-MD-d80abce6eb-one-retry-for-stream-flakes.md](./2026-07-05-26/AGENTS-MD-d80abce6eb-one-retry-for-stream-flakes.md)

**Proposed agent instruction** (verbatim from the per-rule file's `# agent instruction` section):

> **One retry for stream flakes.** On MCP errors like "permission stream closed before response received", retry the identical call once before investigating. Expect MCP servers to disconnect and reconnect mid-session; deferred tools need a ToolSearch load before first call and after a server flap.
>
> *Grounded in: the Mermaid validator failing with a stream-closed error and succeeding verbatim on retry; the GitHub MCP server flapping twice mid-session.*

**Justification** (verbatim from the per-rule file's `# justification` section):

Both failure signatures look alarming and both were self-healing in the task-01 session. The rule converts a would-be debugging detour into a single retry, and the flap expectation prevents the worse move: declaring a capability unavailable and re-planning around a tool that returns thirty seconds later.

### Suggestion 9: Grep before re-Edit — `AGENTS-MD-e8a2ee6701`

- **Per-rule file**: [./2026-07-05-26/AGENTS-MD-e8a2ee6701-grep-before-re-edit.md](./2026-07-05-26/AGENTS-MD-e8a2ee6701-grep-before-re-edit.md)

**Proposed agent instruction** (verbatim from the per-rule file's `# agent instruction` section):

> **Grep before re-Edit.** If an Edit fails with "string not found" on a file written earlier in the session, do not retype from memory — grep the target region (`grep -n -C 4 'anchor phrase' file`) and rebuild old_string from the output, respecting the actual line breaks.
>
> *Grounded in: an Edit to the A-VS definition failing because the remembered line-wrap point differed from the file's; one grep recovered the exact text and the retry succeeded.*

**Justification** (verbatim from the per-rule file's `# justification` section):

Prose written at one wrap width and edited from memory at another fails string-matching even when every word is right. The recovery is mechanical and always the same; encoding it saves the second and third blind retry.

### Suggestion 10: Deliverable-only PRs — `AGENTS-MD-c016bdd53a`

- **Per-rule file**: [./2026-07-05-26/AGENTS-MD-c016bdd53a-deliverable-only-prs.md](./2026-07-05-26/AGENTS-MD-c016bdd53a-deliverable-only-prs.md)

**Proposed agent instruction** (verbatim from the per-rule file's `# agent instruction` section):

> **Deliverable-only PRs.** A task PR contains exactly the files the task's Deliverables section names. Analysis substrates (inventories, scratch evidence) stay out unless the task asks for them. Reproduce the task's acceptance checklist, ticked, in the PR body; reference the umbrella issue (#22) without closing it; leave task files unedited — completion is recorded by the merge, not by editing the queue.
>
> *Grounded in: PR #26 shipping two files against a session that produced six-plus analysis artifacts, with the task-01 checklist ticked in the body.*

**Justification** (verbatim from the per-rule file's `# justification` section):

The work queue (`spec-completeness/tasks/`) is the owner's tracking surface and the umbrella issue spans three tasks; a PR that closes #22 or rewrites task files corrupts both. The ticked checklist in the body gives the reviewer the acceptance test without archaeology. (If you would rather keep evidence packages in the repo, invert the middle clause — but decide once, here; see the companion ADR draft on evidence retention.)

### Suggestion 11: Merge mechanics — `AGENTS-MD-2eefac90e1`

- **Per-rule file**: [./2026-07-05-26/AGENTS-MD-2eefac90e1-merge-mechanics.md](./2026-07-05-26/AGENTS-MD-2eefac90e1-merge-mechanics.md)

**Proposed agent instruction** (verbatim from the per-rule file's `# agent instruction` section):

> **Merge mechanics.** This repo has no CI — do not wait for checks before declaring a PR ready. Merge via merge commit (repo convention). After a designated branch's PR merges, follow-up work restarts the same branch name from origin/main and opens a new PR — never stack commits on merged history.
>
> *Grounded in: PR #26 showing zero check runs; the merge-commit history of PRs #1–#26; the task-01 retrospective riding a restarted branch.*

**Justification** (verbatim from the per-rule file's `# justification` section):

Each fact was discovered by probing during the task-01 session (an empty check-runs call, a scan of merge history). Three lines in the agents file convert those probes into zero-cost knowledge for every future session, and the branch-restart rule prevents the one git state that is genuinely painful to unwind — new commits stacked on already-merged history.
